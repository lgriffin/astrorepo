# C4 model

The app drawn at three levels of the [C4 model](https://c4model.com): who and what it talks to
(context), what runs where (containers), and the parts of the hexagonal core inside the desktop
app (components). Every slice that adds a port, an adapter or an external tool updates these
diagrams in the same pull request, so they always match `main`. Parts marked *planned* are in the
roadmap but not built yet.

## Level 1 · System context

```mermaid
C4Context
  title Astrorepo: system context
  Person(leigh, "Astrophotographer", "Captures with a Seestar S50, a Vespera Pro, or a DSLR or cooled camera; plans, stacks and processes on a Windows PC")
  System(astro, "Astrorepo", "The cockpit: finds what is in the capture folders, says what to do next, plans nights, and runs the tools that do the pixel work")

  System_Ext(scopes, "Smart telescopes and cameras", "Seestar, Vespera, DSLR, cooled camera: write FITS, TIFF or camera RAW")
  System_Ext(nas, "Synology NAS", "Holds every capture, stack and finished image")
  System_Ext(siril, "Siril and Siril_Scripts", "Stacking, plate solving when ASTAP is missing, and post-processing scripts")
  System_Ext(rcastro, "RC Astro CLI", "BlurXTerminator, NoiseXTerminator, StarXTerminator")
  System_Ext(syqon, "SyQon CLI", "syqon-cli: Axiom, Prism, Parallax and Deep Gradient models, run locally; installed by the user, never bundled")
  System_Ext(astap, "ASTAP", "Preferred plate solver, with its own star database")
  System_Ext(spark, "DGX Spark (Ollama)", "AI helper on the LAN (slice M, planned)")
  System_Ext(weather, "Weather forecasts", "Open-Meteo or MET Norway (public, keyless), and the user's own weatherlink_website service")

  Rel(leigh, astro, "Uses")
  Rel(scopes, nas, "Files copied to")
  Rel(astro, scopes, "Copies Vespera observations off, over its Wi-Fi", "FTP, read-only")
  Rel(astro, nas, "Reads captures from, writes archives to")
  Rel(astro, siril, "Runs")
  Rel(astro, rcastro, "Runs through Siril_Scripts")
  Rel(astro, syqon, "Runs")
  Rel(astro, astap, "Runs")
  Rel(astro, spark, "Asks for captions (planned)")
  Rel(astro, weather, "Asks for the next nights' forecast (rounded coordinates only)", "HTTPS, JSON")
```

## Level 2 · Containers

```mermaid
C4Container
  title Astrorepo: containers on the Windows PC
  Person(leigh, "Astrophotographer")
  System_Boundary(pc, "Windows PC") {
    Container(ui, "Renderer", "React 18, Vite", "Pages: Home, Targets, Sky planner, Jobs, Files (Gallery, Vespera), Review, Collections (Mosaics, Messier mosaic), Setup")
    Container(main, "Main process", "Electron, Node 20, TypeScript", "IPC handlers, the hexagonal core, adapters, the job runner and the Vespera copy queue")
    ContainerDb(db, "Index", "SQLite (better-sqlite3)", "FITS and camera RAW frames, targets, comet orbits, grades, jobs, manifests, archives, palettes, solves, settings")
    Container(work, "Work area", "Folder on a local SSD", "Siril work folders (one per filter for mono), comet positions files, staged outputs, job logs, archives until an archive folder is set")
  }
  System_Ext(nas, "Synology NAS")
  System_Ext(tools, "External tools", "Siril, Siril_Scripts, RC Astro, SyQon CLI, ASTAP")

  Rel(leigh, ui, "Uses")
  Rel(ui, main, "Calls", "IPC (contextBridge, zod-validated)")
  Rel(main, db, "Reads and writes")
  Rel(main, nas, "Reads captures (never writes to source folders)")
  Rel(main, work, "Lays frames out, stages outputs, removes intermediates the user confirmed")
  Rel(main, nas, "Writes target archives to the archive folder")
  Rel(main, tools, "Runs as child processes", "argument arrays, never a shell")
  Rel(main, nas, "Adds Vespera copies to the landing folder (new files only)", "FTP from the scope at 10.0.0.1")
  Rel(tools, work, "Write results to")
```

## Level 3 · Components of the main process

The core is `packages/domain` (pure rules) and `packages/application` (use cases and the ports
they need). Adapters in `src/main/adapters` implement the ports; `src/main/composition.ts` is the
only place they meet. The tool hub is the gateway every external program goes through.

```mermaid
C4Component
  title Main process: the hexagonal core and its adapters
  Container_Boundary(core, "Core (packages/domain, packages/application)") {
    Component(discovery, "Discovery and next actions", "Use cases", "Hidden data, ranked next actions, stacking suggestions (specs 010, 013)")
    Component(planning, "Forward planning", "Use case", "Tonight, seasons, moon (spec 012)")
    Component(stacking, "Stacking plan", "Use cases", "Script choice, disk and memory estimate, drizzle and rejection advice, multi-night plan (specs 014, 020)")
    Component(grading, "Frame grading", "Use cases", "Measure, grade, override and export subframes (spec 019)")
    Component(jobs, "Job runner", "Use case", "Run window, idle rules, staged outputs, manifests, known failures (specs 016, 021)")
    Component(archive, "Archive", "Use case", "Linked or self-contained target archives; space each intermediate frees (spec 022)")
    Component(hub, "Tool hub", "Use cases", "Finds tools, their versions and catalogues, SyQon's models; builds every command; one exit-code contract (specs 015, 023)")
    Component(sky, "Sky geometry", "Use cases", "Plate solves (ASTAP preferred, Siril fallback), misfiled check, mosaic planner, panel grouping (spec 024)")
    Component(gallery, "Gallery inspector", "Use case", "Histograms, palettes, compare, coordinate overlays from headers or stored plate solves (spec 025)")
    Component(pictures, "Gallery", "Use case", "Finished pictures in the images folder, each matched by its name to catalogue objects, with a side panel (spec 031)")
    Component(rigs, "Other rigs", "Use cases and rules", "Camera RAW in the plan, one stack per filter, the filter for tonight, comet positions (spec 026)")
    Component(workspace, "Mosaic workspace", "Use cases", "Versioned grids on the sky: panels with ICRS centres and footprints, revisions, CSV/JSON export, solved captures placed by footprint overlap with manual overrides (spec 037)")
    Component(messier, "Messier mosaic", "Use case", "110 tiles with the user's own pictures, states, when each gap is up, gaps for Next actions (spec 032)")
    Component(vespera, "Vespera ingest", "Use cases", "Scan sessions from listings, name targets, plan and copy with resume, SHA-256 manifest, one copy queue (specs 033, 034)")
    Component(skies, "Clear skies", "Use case", "The next three nights' dark windows judged against the forecast and the user's weather service, answers kept 30 minutes (spec 036)")
  }
  Container_Boundary(adapters, "Adapters (src/main/adapters)") {
    Component(sqlite, "SQLite adapters", "better-sqlite3", "Frame catalogue, grades, jobs, manifests, archives, comet orbits, plate solves, mosaic plans, mosaic workspaces, gallery catalogue, palettes, object catalogue")
    Component(nodefs, "File system adapters", "Node fs", "Siril work area, content hasher, FITS and PNG pixel readers on worker threads, TIFF and EXIF reader for camera RAW, job logs, archive area, the gallery's picture folder (shrunk by Electron's image decoder)")
    Component(proc, "Process runner", "child_process", "Below-normal priority, kills the whole tree")
    Component(toolhub, "Node tool hub", "Node fs", "Setting, PATH, SYQON_CLI_PATH, standard folders; catalogue folders listed")
    Component(apppaths, "App Paths registry", "reg query", "HKLM and HKCU App Paths, argument array, read only")
    Component(probe, "Tool probe", "child_process", "Version flags and SyQon's --list-models, ten-second limit")
    Component(eph, "Ephemeris", "astronomy-engine", "Sun, moon, sidereal time and the Earth's position")
    Component(solvers, "Plate solvers", "Node fs, through the process runner", "ASTAP command line and Siril's solver over a hard link or copy in the work area")
    Component(ftp, "Vespera scope", "Node net", "FtpVesperaScope over NodeScopeFiles: an FTP client that sends only read-only commands, one call at a time")
    Component(ingestdisk, "Ingest disk and transfer store", "Node fs", "NodeIngestDisk (.part files, free space), FileVesperaTransferStore (astrorepo.transfers.json), NodeVesperaMetadata (EXIF, FITS header)")
    Component(weathersrc, "Weather sources", "Node fetch", "OpenMeteoSource, MetNorwaySource and WeatherServiceSource (weatherlink_website), 15-second limit")
  }
  ComponentDb(db, "Index", "SQLite")

  Rel(discovery, sqlite, "FrameCatalogue, DismissalStore")
  Rel(grading, nodefs, "FrameMeasurer")
  Rel(grading, sqlite, "FrameGradeStore")
  Rel(gallery, nodefs, "ImagePixels")
  Rel(gallery, sqlite, "GalleryCatalogue, PaletteStore, SolveStore")
  Rel(pictures, nodefs, "PictureFolder")
  Rel(pictures, sqlite, "ObjectCatalogue, PlanningSettings")
  Rel(stacking, nodefs, "SirilWorkspace")
  Rel(jobs, proc, "ProcessRunner")
  Rel(jobs, sqlite, "JobStore")
  Rel(jobs, nodefs, "RunArea")
  Rel(archive, nodefs, "ArchiveArea")
  Rel(archive, sqlite, "ArchiveStore, JobStore")
  Rel(discovery, sqlite, "ArchiveStore")
  Rel(hub, toolhub, "ToolHub")
  Rel(toolhub, apppaths, "AppPathsRegistry")
  Rel(hub, probe, "ToolProbe")
  Rel(planning, eph, "Ephemeris")
  Rel(sky, solvers, "PlateSolver")
```

## Keeping the diagrams honest

- A new port appears as a labelled relation in the component diagram, named as the interface is.
- A new external program appears in the context diagram and goes through the tool hub.
- `tests/architecture/hexagon-boundaries.test.ts` enforces the boundaries the component diagram
  draws: the domain imports nothing outside itself and the application imports only the domain.
